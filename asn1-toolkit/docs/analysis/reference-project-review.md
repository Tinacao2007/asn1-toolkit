--------------------------------------------------------------------------------
1. PASN1
--------------------------------------------------------------------------------
位置: /mnt/f/ASN_1/pasn1/
结构: VS_pasn1/, doc/, export/, tools/ (act/, asn1lib/, easn/)
版权标记: 工具文件包含 "Copyright (C) Procodec Communications Co." (如 act-util.h)
与 asn1-toolkit 关系: ARCHITECTURE.md 明确提及为反面参考 — "parser.h 旁边混合了
ber-gen-enc.h 和 uper-gen-enc.h"，即解析器与编解码生成器混合在同一编译器中。
审查发现:
  - pasn1/tools/act/ 为基于 lex/yacc 的构建体系 (lex-asn1.c, Makefile)
  - 设计模式与 asn1-toolkit 的严格分离 (AST/IR/codegen/runtime) 形成直接对比
  - 同属 Procodec 家族 (版权同源)，说明 pasn1 是早期/实验版本，asn1-toolkit 是重构后的规范版本
风险/差异: pasn1 的混合模式正是本项目要避免的陷阱 (文档第 8 行)

--------------------------------------------------------------------------------
2. Python_asn1tools
--------------------------------------------------------------------------------
位置: /mnt/f/ASN_1/Python_asn1tools/
身份: Python 包 (asn1tools)，支持 BER/DER/GSER/JER/OER/APER/UPER/XER
限制 (README 直接声明):
  - CLASS (X.681) 及其相关语法不支持
  - 参数化 (X.683) 不支持
  - EMBEDDED PDV 不支持
  - ANY / ANY DEFINED BY 不支持 (已从 1994 标准移除)
  - WITH COMPONENT / WITH COMPONENTS 约束被忽略 (OER REAL 除外)
  - DURATION 类型不支持
  - 仅支持 "subset" 语法
代码生成: 仅对 OER 和 UPER 提供 C 源码生成 (有局限)
与 asn1-toolkit 对比:
  - asn1-toolkit 已实现 CLASS / 对象类 / 表约束 / 信息对象语法 (parser_ioc.cpp, ast/ioc.hpp)
  - asn1-toolkit 实现了完整的约束系统、类型 IR、代码生成 (不仅限于 OER/UPER)
  - Python 版本为解释型工具，适合快速原型；C++ 版本为生产级编译器/运行时
结论: Python_asn1tools 是轻量参考实现，功能覆盖远小于本项目，不构成竞争替代

--------------------------------------------------------------------------------
综合对比结论
--------------------------------------------------------------------------------
维度                asn1-toolkit (本项目)      参考项目
------------------- --------------------------- --------------------------------
语言/构建         C++17 / CMake 3.16+          pasn1: C/lex-yacc; Python: Python
编解码覆盖         BER/DER/PER/OER/COER/         Python: 同名但功能受限 (无 CLASS,
                   XER/CXER/EXER/JER/JERI      无参数化, WITH COMPONENT 忽略)
编译器架构         AST/IR/codegen 严格分离      pasn1: 解析器与生成器混合 (反面)
代码生成           多编码规则、生成 .cpp        Python: 仅 OER/UPER C 生成 (有限)
对象类/信息对象     支持 (parser_ioc, ast/ioc)    Python: CLASS 不支持
电信 fixtures      RRC/LPP/S1AP 完整 fixtures    无 (Python 仅有小型测试)
版权/状态           PROCODEC 商业化 (2026)       pasn1: 同源 Procodec; Python: 开源
测试               CTest + GoogleTest           Python: 自带测试 (较小规模)

核心发现:
1. pasn1 与本项目同属 Procodec，且 pasn1 的混合设计被本项目文档明确列为要避免的陷阱，
   证明 asn1-toolkit 是对早期实现的规范重构，而非简单扩展。
2. Python_asn1tools 是功能受限的开源参考实现，覆盖范围远小于本项目，不构成功能重叠竞争。
3. FFASN1dump、ASN1C 为外部工具/编译器，无源码交集；ASN1-Compiler 为未完成原型；
   Wireshark_ASN.1 为空目录。
4. 本项目在架构严谨性、编码规则覆盖、电信验证、代码生成能力上均明显优于所有可审查参考项目。

- 对 Wireshark_ASN.1 空目录确认是否有外部参考需求
- 对 pasn1 的工具链 (act, asn1lib) 可做更深的代码级差异分析 (若需要)
